StaffFlow v0 — UI mockups

Sham Cash · internal · 12 agents, 1 team lead, 1 branch manager · Arabic RTL · desktop 1440×900 (fluid to 1280) · IBM Plex Sans Arabic · Western digits, tabular.

Files

  • StaffFlow.dc.html — the clickable prototype. Log in (any username + password), then use the dashed role switcher in the bar. The demo clock runs at 10× so overrun and auto-end happen within a minute; the Tweaks panel switches tile layout (a/b/c), the dark board, clock speed and start scenario.
  • This page — tile options (1a–1c), the 10 screens with their states, the components sheet and tokens. Every screen below is the live prototype pinned to a state.

Decisions to confirm

  • Logo — not attached, so the mark is a placeholder drawn from the description (two-part hexagon, indigo top-right, green bottom-left, on navy). Drop in the real SVG and nothing else moves.
  • Red is overrun only — login and form validation therefore use the accent (indigo tint + "!" marker), never red. Leave-status chips are neutral too: indigo tint = قيد المراجعة, navy fill = مقبول, outlined grey = مرفوض / ملغى / تم سحب الموافقة.
  • Agent on break — the status card follows the board's semantics (amber, turns red on overrun with the label تجاوز المدة); break buttons grey out without a label while a break is running, since neither neutral label applies.
  • Corrections — actions live on ended sessions; a voided session stays listed, struck through, carrying معدّل. حفظ is disabled until the note is typed.
  • Cap change — picking a new number opens a confirm ("من 2 إلى 3", حفظ / إلغاء) so the audit-logged change is deliberate.
  • Dark board — status colours lifted one step; chips use navy text on the lifted colour for legibility.
  • Sample data — your 12 names; reasons and the correction note are placeholder data (not UI copy). Sim clock 10:42, 09/09/2026.
