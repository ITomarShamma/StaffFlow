| 2026-09-09 | Service host | NSSM rather than pm2 (see `docs/DEPLOY.md` §3). |
| 2026-09-09 | Demo-day pitfall | If the demo runs on a Thursday, "daily leave for tomorrow" is a Friday and costs 0; the e2e pins a Tuesday. |
| 2026-09-10 | Team Lead and leave (user) | The Team Lead requests leave like an agent (`/lead/leave`, same balance rule, same Branch Manager decision), may cancel their own pending request, and appears as a tile on the **Branch Manager's** board only, marked «مشرف», with no break budget. Balances and the daily summary list agents first, then the Team Lead. The Team Lead still takes no breaks (spec §3). |
| 2026-09-10 | Date fields (user) | Leave dates and the summary date use the browser's calendar picker (`<input type="date">`, ISO values) instead of the design's dd/mm/yyyy text fields. Times stay HH:mm text. |
| 2026-09-10 | e2e server | The Playwright run serves a production build (`next build` + `next start` on port 3100) so it can run while `npm run demo` is open in another terminal. |
| 2026-09-10 | Time fields (user) | Times are picked from hour/minute wheels (`src/components/TimePicker.tsx`), bounded by the branch work hours so an impossible time cannot be chosen; the text box stays typable for speed. Supersedes the 2026-09-09 "Time inputs" row for the leave form and the corrections dialog. Still not `<input type="time">`, which browsers render in the OS locale. |
| 2026-09-10 | Leave refusals (user) | `validateSubmission` returns one code per cause instead of a single `invalid_window`, and the form shows that message under the field that caused it. Accept / reject outcomes are unchanged — only the reason given is finer. New copy carries `// TODO-COPY` in `src/i18n/ar.ts` for review. The leave form is `noValidate`: the browser's native constraint bubble was blocking submits silently and in the browser's own language. Server actions for submit, cancel and decide now return `server_error` instead of throwing. |
| 2026-09-10 | Fri–Sat daily leave | Left as spec §6 has it: a Friday–Saturday range is accepted and costs 0 minutes. Refusing it would be a rule change, so it stays a question rather than a silent edit. |
| 2026-09-10 | Mis-click safety (user) | A break shorter than `min_session_s` (seeded at 15 s) counts for nothing: no budget minute, no allowance slot, no board counter, no summary line, and it is not listed in Corrections. The row stays in the database for audit. Only an **ended** session can be discarded — an open one is real, the agent is off the floor however briefly. Implemented as `isDiscarded`/`countable` in `src/domain/budget.ts`, applied inside `canStart` and `dailySummary` so a caller cannot forget it. |
| 2026-09-10 | Call break (user) | Fifth break type `call` «مكالمة هاتفية»: **no** concurrency cap (`pool: "none"`, unlimited simultaneous calls), **no** maximum duration, **no** daily limit, and **outside** the 25-minute budget — so it can never overrun. A forgotten call is closed by the system after 10 minutes and marked «لم يُسجَّل الإنهاء», the same treatment as a stale toilet break. Counted in the daily summary and the CSV as «مكالمات — العدد». No schema migration: break types are seeded data, but an existing database needs `npm run db:reset` (or a manual row) to gain it. |
| 2026-09-10 | No backdated leave (user) | A leave request may not begin before today (Asia/Damascus, server clock): `date_past` for hourly, `start_date_past` for daily. Today itself is accepted. The date pickers also carry `min=today`. **This reverses decision Q22 of 2026-09-09**, which accepted any date so a late arrival could be filed after the fact; that is no longer possible and would need a Team Lead correction path instead. The check is skipped when no `today` is supplied, so the domain stays callable without a clock. |
| 2026-09-10 | Reference-data upgrades | Adding a `Config` key or a `BreakType` row broke every page of a **running** install: `parseConfig` refuses a missing key (deliberately — a business rule must not be silently defaulted) and the seed is destructive, so there was no way to top up a live database. `npm run admin -- sync` now inserts missing break types and config keys from `prisma/seed-data.ts`, never overwrites an existing value, and never touches users, sessions or leave. It is part of the documented upgrade sequence. |
| 2026-09-10 | Working week (user) | The branch works **Saturday to Thursday**; only Friday is off. `working_days` is `6,0,1,2,3,4` (0 = Sunday, 6 = Saturday), replacing the spec's Sun–Thu. Consequence for leave: a daily range now costs the Saturday, so Fri–Sat is 8 h rather than 0, and only a Friday-only request still costs nothing. The demo-day pitfall shrinks accordingly: "leave for tomorrow" is free only when tomorrow is a Friday. Applied to a live database with `npm run admin -- set-config --key working_days --value "6,0,1,2,3,4"`. |
| 2026-09-10 | Changing a setting on a live install | `sync` deliberately never overwrites an existing value, so it cannot change a rule. `npm run admin -- show-config` lists every setting and `set-config --key K --value V` changes one, validating the whole configuration through `parseConfig` **before** storing, so a bad value is refused at the command instead of taking every page down on the next request. |
